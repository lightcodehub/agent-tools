# 设计文档核查

核查从模板应有的项目出发。用户指定全仓时，对照总设计索引、实际目录及模块源码盘点范围，补查索引外或缺少文档的模块。局部核查只处理授权范围及必要契约。输出、修订后对最终版本执行相同核查。

1. **生成底表。** 在当前 architect skill 目录定位 `scripts/audit_design.py`，用 Python 3.9+ 对消费项目设计目录运行 `python3 "$architect_dir/scripts/audit_design.py" --root "$design_dir" --file "$module_doc" --view inventory`（`module_doc` 为已确定的模块文档相对路径）。大结果保存到允许的临时产物位置并分文件读取；只读任务在内存中处理。日常迭代先按[模块依赖与影响](scoped-reading.md#索引与范围)确定应审模块，对每份相应文档传入 `--file 相对路径`。全仓任务将 `--file` 及其参数替换为 `--all`。局部迭代中若应有模块文档缺失，报告具体模块及路径。完整底表保留文档与已解析契约目标的 SHA-256 快照和 Markdown 可见正文的行号映射，供后续核查同版复用。脚本或语法不可用时用等价解析逐项盘点，说明限制。仅列出目录、抽样或只遍历已有链接不足以完成核查。
2. **逐文件对模板。** 从文件头开始核对，按适用模板检查元信息字段、顺序和值。“所属设计”直接链接总设计首页，显示其一级标题的完整可见文字；“所属服务”直接链接服务总览首页，显示标题中的服务名。总设计或服务更名时复核受影响的归属引用。 底表同时给出模板要求和实际章节、表头、行号、定位字段及 Markdown 内联锚点链接。以实际文档类型选模板，逐项核实必需章节与表格、字段顺序、每行的值、状态与章节归属。依据设计事实判断条件项是否适用。总设计、模块设计和外部服务总览在成稿或核查时运行 `python3 "$architect_dir/scripts/table_headers.py" --kind <design-index|design-module|api-service> 文档路径`，按实际文档选择一种类型。逐列核对名称、顺序和行宽，合并列中的名称直接链接到对应文档或定义。处理底表中的全部结构差异，检查省略的栏目、无链接的文本以及解析器未识别的引用形式。最终写入后以相同范围运行 `audit_design.py --view format`（保留 `--root` 和范围参数）。逐处核对输出的文件、行、规则及对象；退出码 1 表示仍有待处理项。修正后重跑，解析受限或合法例外须给出相应条款和实际文本。使用已安装 `markdown-it-py` 的 Python 运行底表和最终检查；`正文渲染边界` 给出实际节点、行号与表格列。按同一格式项处理所有确认的正文偏差；实施计划链接、集成用例表、服务公共约定及协议参数与返回表按模板和实际适用性逐项核实。通过 `--view rendered` 按文件取得完整节点序列，结合上下文逐项验明，包括未触发提示的段落。若当前解释器缺包，换用已有可用解释器，或用项目渲染器核查等价的完整预览。仅扫描源码、表头或抽查示例不能判定整稿格式通过。

   “项目文件用途”按实际作用判定：设计正文中的业务源码路径或链接改写为职责与设计契约；保留真实的公共配置、执行命令、测试路径及独立架构模块例外，按文件归并说明依据。核对 §8.2 每个场景的本行或组头落点。从“验证关联”反查已有用例 ID 和候选定义，再以实际断言确认归属；往返链接一致也可能同时沿用过宽的编号区间，逐项区分被测功能、准备动作和观察手段；单纯编号、测试文件与大章标题不能证明定位。逐文件复核交互用语、调用片段和用例输入/预期的渲染，结合实际接口或断言判断角色未曾标记过的字面值。另将每个功能索引的两个落点与功能、实际调用逐一对照；格式检查通过仅说明其覆盖的结构项符合。

3. **逐契约取证。** 逐行比对使用方的行为、实际调用或已确认设计、目标章节所定义的操作或类型。对功能索引同时查看功能列与其 API 列的目标正文，再回到相应实现或调用点确认。不同功能复用同一索引目标时逐个核实；只有共享入口确实承载各自行的行为才符合。对依赖、调用方、外部协议和正文中的契约引用采用同样方法。锚点存在、标题与目标一致都不能证明指对契约。可按目标复用已读证据，仍须确认每一条引用的使用方。逐项核实设计与需求、用例断言、实施步骤、验收状态的对应关系。
4. **按底表收口。** 将每份文档的模板项、契约引用对到核查结果；可分组复用证据，保留适用的文件、行或章节以及核对依据。最终渲染的候选逐项判为已修正、符合（说明该词或组头在原句中的用途）或未核实；同一依据可归并多个位置。有确认偏差或未核实项时不标记整稿格式通过。已确认的偏差全部可定位，同类项可按文件和章节列行号或区间，长清单可引用本轮临时明细。未查到的事项列出范围和原因，未完成的项不能计为符合。仅核查时交付发现；修订时在授权范围内纠正，重新盘点并核对修后成稿。
