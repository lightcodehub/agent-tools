# 专项设计

只填写任务实际涉及的技术条件。缺少影响实施的资料时说明影响、确认方与适用范围，不把未决选择写成既有配置。

## 界面与组件

先核对已有设计稿、项目组件、设计系统和同类页面。已有适用设计稿时直接引用。缺少设计稿时，若需求和既有约定足以确定布局、操作流程及关键状态，直接绘制线框草案。若仍有影响行为且必须由用户决定的问题，先集中确认，再绘制受影响的界面。

所有新绘制的线框图均使用 SVG，以矢量元素表达页面区域、控件和文字，保存为 `.svg` 文件。模块 §6 用相对路径嵌入线框图，随本版设计交用户审核，并说明相应状态与行为。组件按“已有组件 → 项目组件工具集 → 开源组件 → 自研”的顺序选择并说明依据。

总 §5.3 链接已有视觉资料。确需单独维护时，用[视觉模板](../assets/visual-spec.md)生成 `design-doc/visual-spec.md`。主题、语义令牌、字体、间距和圆角等取自项目或用户已确认的选择；影响行为的未决事项按上述条件确认。

## 持久化

在模块 §4/§5 定义实际类型及存储结构；按需给出表关系与 ER 图、字段、约束、索引和用途。涉及结构或数据变更时说明兼容、迁移及必要回滚条件，优先复用项目已有机制。没有对应变更不新增迁移要求；不为填模板制造数据实体或默认技术选型。

## 外部服务

核实需求、既有 client 和接口资料。外部调用成立但缺少文档时请用户提供或确认契约，不把假设写成服务保证。在 `design-doc/external-service/{name}/` 使用[服务总览](../assets/api-service.md)和[API 模块](../assets/api-module.md)，模块文件按业务命名，列明已核实的地址、认证、参数、返回及错误。调用方 §1.3 以相对链接定位接口；本地调用行为、测试和验收归调用方。服务契约资料没有实施状态、测试计划或验收，不替外部项目设计其内部实现。
