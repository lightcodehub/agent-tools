## 1. 模块概述

**模块职责**: 异步消费导出任务，根据筛选条件生成 CSV 文件并更新任务状态。

**业务边界**:

- 负责: 接收 job runner 投递的任务 ID、查询订单、生成 CSV、上传文件、更新状态
- 不负责: 任务创建与查询接口（由 task 模块负责）

## 2. 内部设计与共享规则

### 2.1 内部职责与状态归属

worker 负责领取、执行导出、上传、提交结果以及回收其取得的流；生成器负责读取订单并输出 CSV；runner 负责注册和调用处理函数。任务持久化及允许的状态更新归 task 所有，本模块通过功能契约请求迁移，不直接访问任务表。代码位置见“1.4 实现映射”，不额外固定普通私有辅助函数。

### 2.2 共享依赖与资源所有权

处理导出和生成 CSV 使用 task 唯一维护的 [OrderFilters](../task/index.md#orderfilters)，不复制筛选类型或增加默认条件。生成器创建的流交给 worker 后，由 worker 回收；生成器仍负责自身取得的查询资源，二者均不关闭借用的共享 client。各功能内定义自己的获取、失败与清理路径，worker 的终态和错误优先级不扩散为其他功能的通用规则。

### 3.1 处理导出任务

**目的与触发**: runner 投递任务标识后，取得处理权、生成并上传文件，将结果关联到可查询的任务。

**前置与输入**: task 的领取与提交结果契约可用；任务标识由 runner 原样传入，只有领取成功后才能执行业务。上传 client 的具体输入映射仍受“11. 未决问题”约束。

<a id="api-process-export-task"></a>

#### `processExportTask(taskId: string): Promise<void>`

**简介**: 领取导出任务，按任务快照生成并上传 CSV，再提交处理结果。

**参数**:

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `taskId` | `string` | 是 | 待处理的导出任务 ID |

**返回**: `Promise<void>`。领取返回 `null` 时正常跳过；生成和上传成功时，将存储返回的 `fileUrl` 与 `success` 一起写回，经 task 确认后尝试回收流并正常返回。导出结果通过 task 查询。

**错误**: 领取异常原样传播。领取成功后，按下表处理业务与写回错误，回收本次取得的流后再向调用方传播异常。

| 阶段结果 | 写回 | `processExportTask` 的结果 |
| --- | --- | --- |
| 查询、生成或上传失败 | 请求 `failed` 及安全摘要 | 写回成功后传播原业务异常对象 |
| 任一结果写回抛异常 | 不再请求另一个终态 | 传播原状态更新异常；若已有业务失败，只保留安全阶段摘要用于诊断 |
| 任一结果写回返回 `null` | 不覆盖已有状态，不重试写入 | 抛任务状态冲突错误，不声称本次已写入成功 |

**处理规则**:

```mermaid
flowchart TD
    A["收到 taskId"] --> B["调用 task 契约领取 pending → running"]
    B --> C{"领取结果"}
    C -->|null| D["未取得处理权，正常返回"]
    C -->|异常| X["传播异常，不生成或上传"]
    C -->|任务快照| E["使用领取快照的 filters 生成并上传 CSV"]
    E --> F{"业务结果"}
    F -->|成功| G["调用 task 契约写 success 与 fileUrl"]
    F -->|异常| H["调用 task 契约写 failed 与安全摘要"]
    G --> I["保存写回结果或异常"]
    H --> I
    I --> J["回收本次取得的流资源"]
    J --> K["按契约返回或传播选定异常；不覆盖终态、不重传"]
```

**处理规则与处理权**: 仅通过 task 的 [领取](../task/index.md#claim-task)、[提交结果](../task/index.md#submit-result) 功能及其 [共用更新契约](../task/index.md#transition-contract) 使用 `transitionExportTask` 更新任务，不直接写任务表。首先请求 `{status: 'running'}`；返回 `null` 时不查询订单、不生成或上传、不继续写状态。只有取得 `running` 快照的调用才能执行后续业务，筛选条件取该快照，不另读后自行判断可处理性。

安全摘要按 worker 正在等待的接口调用分类：`generateCSV` 拒绝使用“CSV generation failed”，上传调用拒绝使用“File upload failed”（包括消费 CSV 流时失败）；不解析原始异常文本猜测原因。

状态更新异常可能对应尚未提交或结果未知，不能将上传成功后的写回失败转换成 `failed`，也不能根据异常断言数据库已回滚。worker 不自动重新领取、重传或删除已上传文件；后续通过 task 查询核对状态。不存在任务的错误按任务服务契约传播。

**资源与错误边界**: worker 回收本次实际取得的 CSV 流，覆盖完成、失败或已有执行器支持的取消路径；沿用现有流与 client 的生命周期接口，避免重复关闭。已获得的业务结果先尝试写回，写回抛错或冲突也必须进入清理。存在待传播的业务、状态更新或冲突异常时，清理错误不替换它；成功终态已经持久化后发生清理故障时，保持 `success` 和原 `fileUrl`，不拒绝 `Promise`、不重新上传。worker 不修改已持久化的 `errorMessage` 来记录清理故障。

worker 使用项目已有 logger 在领取成功后记录处理开始，仅在状态写回确认成功时记录相应终态；写回失败或冲突单独报告处理诊断，不伪称任务已完成。上下文只包含已允许且实际可取得的 `userId`、`taskId` 和安全错误码，不记录凭据、完整筛选条件、订单内容或未经允许的原始异常文本。纯 CSV 字段转换逻辑不新增日志。

清理故障由 worker 汇总为一次错误事件，只包含可用 `taskId` 和安全错误码 `cleanup_failed`，不附原始异常文本、订单内容或上传返回体。该诊断与业务失败或写回诊断各表示不同问题，不逐层重复记录同一错误。

### 3.2 生成 CSV

**目的与触发**: worker 取得处理权后，以任务快照的订单筛选条件请求 CSV 内容。

**前置与输入**: 输入遵循 task `OrderFilters`；复用既有订单查询，具体调用及 CSV 列契约尚待“11. 未决问题”确认，不能用测试数据自行定义业务字段。

<a id="api-generate-csv"></a>

#### `generateCSV(filters: OrderFilters): Promise<ReadableStream>`

**简介**: 根据订单筛选条件生成可流式读取的 CSV 内容。

**参数**:

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `filters` | `OrderFilters` | 是 | 筛选条件 |

**返回**: `Promise<ReadableStream>`，流使用运行环境的 Web Streams 类型。

**错误**: 订单查询失败时，生成调用或输出流以原错误失败，不输出成功文件。生成器不修改任务状态，worker 按[处理导出任务](#process-export)的等待阶段归类并提交失败摘要。

**处理规则**: 空筛选 `{}` 不增加条件；空结果仅含表头，3 条订单产生表头加 3 行；10000 条订单须以流式方式处理而不 OOM。该样例用例只验证流可正常消费且无内存或进程错误，不据此宣称容量上限；字段、表头、转义等完整格式规则及查询/消费能力见“11. 未决问题”，未确认部分不得冒充已有约定。

生成器负责回收其内部实际取得的查询资源，不关闭借用的共享 client；worker 的流回收责任与终态处理遵循 [处理导出任务](#process-export) 的资源与错误边界。

#### 验证关联

[生成器用例](#82-测试用例) `csv-UT-002`、`005` 至 `007`，以及 [8.4 项目内集成验证](#84-项目内集成验证)的 `csv-IT-001`、`003` 实际内容断言。字段映射与格式前提未确认时，不能仅数行就宣称内容通过；大数据量用例通过也不代表已验证系统容量上限。

### 3.3 注册导出处理函数

**目的与触发**: 后台作业初始化时，将导出事件连接到 `processExportTask`。

**前置与输入**: 复用既有 job runner 与实际导出事件，传入值为 `taskId`。当前资料未给出事件名、载荷结构及注册接口，见“11. 未决问题”；不据此新造公开注册 API。

**处理规则**: 注册项绑定导出处理函数；测试初始化注册逻辑后投递 `taskId='1'`，原样调用 `processExportTask('1')` 一次。不得在注册层自行复制领取或结果更新行为。

**结果与副作用**: 形成 runner 到 worker 的调用绑定；处理任务的结果及副作用由“3.1 处理导出任务”定义。

**失败后状态**: 初始化失败、处理函数拒绝时 runner 如何报告、确认投递或重试，当前资料未明确，属于“11. 未决问题”阻塞项；不能推定现有执行器支持特定恢复或取消机制。

[csv-UT-008](#82-测试用例)只验证绑定和参数传递，runner 的真实失败语义须确认后补齐用例。“8.4 项目内集成验证”使用捕获任务的 runner 替身，不证明真实调度的可靠性。

## 7. 影响面与兼容性

- **本模块影响**: 新增 `server/jobs/order-export.worker.ts`
- **对依赖模块的影响**: 只依赖 task 的公开服务契约和共享类型，不依赖表或 repository 内部入口
