## 1. 模块概述

**模块职责**: 异步消费导出任务，根据筛选条件生成 CSV 文件并更新任务状态。

**业务边界**:

- 负责: 从 job runner 拉取任务、查询订单、生成 CSV、上传文件、更新状态
- 不负责: 任务创建与查询接口（由 task 模块负责）

### 1.1 依赖说明

| 依赖模块 | 依赖内容 | 引用章节 |
| --- | --- | --- |
| [task](../task/index.md#32-函数方法接口) | `transitionExportTask` 领取与写回，`getExportTask` 查询；共享类型 `OrderFilters`、`ExportTask`、`ExportTaskChange` | task §3.2 服务契约、§4 类型；不直接调用其 repository 或访问任务表 |

> 真实协作前提：task 的读取与条件更新服务及其 repository 已实现并自测；仅有类型或表结构不足以交验。worker 单测可按已明确的服务契约替换该依赖。

## 2. 核心流程

```mermaid
flowchart TD
    A["收到 taskId"] --> B["调用 task 契约领取 pending → running"]
    B --> C{"领取结果"}
    C -->|null| D["未取得处理权，正常返回"]
    C -->|异常| X["传播异常，不生成或上传"]
    C -->|任务快照| E["使用领取快照的 filters 生成并上传 CSV"]
    E --> F{"业务结果"}
    F -->|成功| G["调用 task 契约写 success 与 fileUrl"]
    F -->|异常| H["调用 task 契约写 failed 与安全摘要"]
    G --> I["保存写回结果或异常"]
    H --> I
    I --> J["回收本次取得的流资源"]
    J --> K["按契约返回或传播选定异常；不覆盖终态、不重传"]
```

## 3. API 定义

### 3.2 函数/方法接口

#### `processExportTask(taskId: string): Promise<void>`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `taskId` | `string` | 是 | 待处理的导出任务 ID |

**副作用与处理权**: 仅通过 [task §3.2](../task/index.md#32-函数方法接口) 的 `transitionExportTask` 更新任务，不直接写任务表。首先请求 `{status: 'running'}`；返回 `null` 时正常结束，不查询订单、不生成或上传、不继续写状态；抛出异常时原样传播。只有取得 `running` 快照的调用才能执行后续业务，筛选条件取该快照，不另读后自行判断可处理性。

**结果写回与返回**:

| 阶段结果 | 写回 | `processExportTask` 的结果 |
| --- | --- | --- |
| 生成与上传成功 | 请求 `success` 及存储返回的 `fileUrl` | 写回成功、资源回收后正常返回；以 task 查询结果判断导出成功 |
| 查询、生成或上传失败 | 请求 `failed` 及安全摘要；生成/查询失败用“CSV generation failed”，上传失败用“File upload failed” | 写回成功、资源回收后传播原业务异常对象，不因记录失败而伪装为成功 |
| 任一结果写回抛异常 | 不再请求另一个终态 | 回收后传播原状态更新异常；若已有业务失败，只保留安全阶段摘要用于诊断 |
| 任一结果写回返回 `null` | 不覆盖已有状态，不重试写入 | 回收后抛任务状态冲突错误，不声称本次已写入成功 |

安全摘要按 worker 正在等待的接口调用分类：`generateCSV` 拒绝使用生成失败摘要，上传调用拒绝使用上传失败摘要（包括消费 CSV 流时失败）；不解析原始异常文本猜测原因。

状态更新异常可能对应尚未提交或结果未知，不能将上传成功后的写回失败转换成 `failed`，也不能根据异常断言数据库已回滚。worker 不自动重新领取、重传或删除已上传文件；后续通过 task 查询核对状态。不存在任务的错误按任务服务契约传播。

**资源与错误边界**: worker 回收本次实际取得的 CSV 流，覆盖完成、失败或已有执行器支持的取消路径；沿用现有流与 client 的生命周期接口，避免重复关闭。已获得的业务结果先尝试写回，写回抛错或冲突也必须进入清理。存在待传播的业务、状态更新或冲突异常时，清理错误不替换它；成功终态已经持久化后发生清理故障时，保持 `success` 和原 `fileUrl`，不拒绝 `Promise`、不重新上传。worker 不修改已持久化的 `errorMessage` 来记录清理故障。

worker 使用项目已有 logger 在领取成功后记录处理开始，仅在状态写回确认成功时记录相应终态；写回失败或冲突单独报告处理诊断，不伪称任务已完成。上下文只包含已允许且实际可取得的 `userId`、`taskId` 和安全错误码，不记录凭据、完整筛选条件、订单内容或未经允许的原始异常文本。纯 CSV 字段转换逻辑不新增日志。

清理故障由 worker 汇总为一次错误事件，只包含可用 `taskId` 和安全错误码 `cleanup_failed`，不附原始异常文本、订单内容或上传返回体。该诊断与业务失败或写回诊断各表示不同问题，不逐层重复记录同一错误。

#### `generateCSV(filters: OrderFilters): Promise<ReadableStream>`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `filters` | OrderFilters | 是 | 筛选条件 |

**返回**: `Promise<ReadableStream>` — CSV 文件流；`ReadableStream` 使用运行环境的 Web Streams 类型

生成器负责回收其内部实际取得的查询资源，不关闭借用的共享 client；worker 的流回收责任与终态处理遵循本节资源与错误边界。

## 7. 影响面与兼容性

- **本模块影响**: 新增 `server/jobs/order-export.worker.ts`
- **对依赖模块的影响**: 只依赖 task 的公开服务契约和共享类型，不依赖表或 repository 内部入口
- **兼容性处理**: worker 独立部署，不影响现有接口
- **迁移/发布注意事项**: 先上线 task 读取/更新契约再部署 worker；未知提交结果、崩溃遗留的 `running` 及已上传孤立文件需经查询核对后按项目恢复流程处置，本示例不增加重置或存储删除接口
