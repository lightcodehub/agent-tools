# 按任务与依赖读取

用于控制进入模型上下文的项目文档和源码范围。先定位、再读取必要正文；文件内容整体相关或切分会破坏必要上下文时可整份读取，否则按章节、符号或调用点分段，不能仅因文件短就展开无关契约。读取范围与修改授权、测试执行范围分别判断，不能为节省 token 缩小必要验收。

## 索引与范围

1. 先遵守适用的仓库指令及已选 skill。已有总设计时，以其 §1 的范围、§3 的模块链接/依赖/契约归属定位目标，再读取适用的 §4/§5 公共约定及 §6.2 未决项；已在上下文中的有效内容不重复加载。总文档负责导航，不复制模块正文、内部文件清单或读取过程。
2. 根据用户范围、输入模块、变更文件或目标符号确定起点。先从目标模块的功能索引逐个定位本次调用的 API 定义，结合所属功能的行为说明，再读所需的共享定义/依赖、影响面、关联测试/实施/验收及相关未决项；任务覆盖整个模块时读完整相关设计，局部任务不默认展开所有模块。
3. 被依赖模块优先读取本次使用的公开契约和引用类型。已有契约锚点时，先定位标题及其结束边界，读取该章节；不要用宽行号范围顺带展开同模块其它工具或测试。契约足够且没有实现疑点时止于该边界，不因依赖存在就递归读取全部传递依赖。契约引用其他定义、需核实接口就绪或定位实际行为时，再读取相应定义与实现片段。
4. 公开接口、共享数据、错误/状态行为或公共配置受影响时，从索引和符号检索定位反向调用方，读取受影响的调用点、契约和测试；内部调整也须核对是否改变外部行为，但不因此打开所有调用方全文。必要依赖与调用方被纳入读取，不等于授权修改它们。
5. 索引缺失、过期、链接失效，或源码出现未记录依赖、动态注册、失败调用链时，依据目录、签名、导入、引用与测试结果补充定位，按证据扩大范围。architect 修正本次相关索引；其他角色按既有衔接处理设计缺口。不能用过期索引排除真实关联，也不把资料缺失当作依赖不存在。

## 读取方式

- 有 Python 3 时，依赖 Markdown 契约按索引锚点使用随附 `scripts/read_section.py`，不要手写宽行号区间代替。脚本路径相对当前 skill 目录：`python3 -B <skill目录>/scripts/read_section.py --root <绝对项目根> <相对文档路径> --anchor <已知锚点>`。不传选择器只列标题；也可用 `--heading` 传列表中的精确标题。脚本只读，按真实标题边界输出，超预算拒绝而不截断；无需状态缓存或额外依赖。
- 脚本支持围栏外的 ATX 标题、独立 HTML 注释及紧邻标题前的显式锚点；遇 Setext 标题或其它不支持的 HTML 块会拒绝输出而不猜测边界。没有 Python 或文档不支持时，用现有工具取得标题边界后等价读取，不自动安装工具，也不退回整篇展开。脚本只控制 Markdown 输出范围，不能代替源码的调用链分析或读取依据判断。

- 优先使用 `rg --files`、文件名/标题/符号检索取得位置，再读相关章节或完整函数、类型及必要上下文。范围明确后限定路径；不要用整目录 `cat`、无限制递归全文或大段重复输出代替定位。输出截断时缩小目标继续读取，不把截断当成已读完。
- 项目 skill 发现先用宿主目录或路径/元数据筛选；只加载命中的 `SKILL.md`，其必需指令仍完整遵守，引用资源按任务需要读取。不为发现能力逐个加载无关 skill 正文，不自动执行发现注册。
- 同一角色、内容未变且正文仍在可用上下文中时复用已读内容；变更后重读改动及受影响上下文。上下文压缩后缺少关键正文时按需重新定位，摘要和文件哈希不能代替行为核对。
- 每次读取前先核对当前上下文已有的路径与内容。已加载且未变的 skill 规则不因进入自检、报告或下一实施步骤再次读取；“按规范核验”是用已读规则检查本次产出，不是再读规则原文。清单中的链接也不是重新加载参考资料的指令。确需补读时应有内容未加载、版本改变、输出截断或关键上下文缺失等具体原因，不能仅为把规则移到最近消息而复读。
- 只复用本上下文中已读的同文规则。独立 validator 从项目文件读取适用规则、设计、实现与测试，不能导入开发对话或过程摘要来节省读取。多份较长规则不要一次拼接成可能截断的输出；按文件或相关章节加载并确认必要内容完整，不能将输出截断误当作已掌握。
- 已有文档结构有效、任务仅定点更新时，复用其结构，不重新加载完整模板或示例。需要新增/纠正章节时只读取对应模板片段；新建文档或无法确认整体结构时再读所需完整模板。不因省略模板重读而省略强制章节或核验要求。
- 公共规范已有有效依据时优先引用；有限范围的源码阅读只能支持相应范围的惯例归纳，不能声称已经核对全项目，也不为局部风格判断读取全仓正文。
- 文件清单、导入枚举、测试发现、哈希与链接检查可由工具批量处理，只返回相关结果和必要诊断；工具处理文件不等于模型必须加载每份全文。先看结构化测试摘要，失败时再打开对应日志、用例与实现。
- 读取依据保留在当前任务上下文即可；交接可附模块、章节/符号、版本及未核实范围，不复制全文或另建长期读取清单。不能声称未读取的内容已经审查。

## 角色要求

| 角色 | 必须覆盖的相关内容 | 不默认展开的内容 |
| --- | --- | --- |
| architect | 需求、目标模块现状、所用依赖契约、受影响调用方及设计/测试/验收对应关系 | 无关模块设计与实现、稳定依赖的内部细节；全项目补档时按模块分批推进，不漏掉授权范围 |
| developer | 本次实现单元的完整行为、关联测试和实施条件，以及直接使用接口的真实定义/就绪证据 | 依赖模块无关实现、无关调用方和全仓正文；不能以只读索引代替编码前设计校验 |
| validator | 重新读取受审实现、相关持久测试及必要调用链，核对本轮证据与设计 | 不以 developer 的判断替代本轮审读；不因全项目回归就逐份加载全仓源码 |

正常验证仍执行既定完整回归与本次集成要求；只审查或限定执行时按原规则说明限制。新失败、未知回归归因或关键前置不成立时须扩大调查。回归通过只证明相应执行结果，不能宣称所有未读代码都已审查。
