# 设计交付自检清单

设计文档写入后、向用户交付前核对。以 `SKILL.md` 和本次需求为依据，本清单不新增设计要求。

适用项满足后标记通过；未满足项注明缺失内容；条件不成立的项目注明“不适用”及原因，不当作失败，也不为勾选而补造内容。迭代时重点核对本次变更及相关引用，保留未变更部分。

## A. 范围与依据

- [ ] 目标、范围、非目标及约束已写明，设计没有扩大本次任务范围
- [ ] 未因用户要求直接实现或改动行数少而排除必要设计；已有充分设计直接复用，缺项仅按本次范围补齐
- [ ] 已查阅相关项目本地 skill；对既有实现的描述有代码依据，新增设计有需求或已确认约束依据，未把推测写成现状
- [ ] 新项目没有现有代码时已如实说明，并明确框架、规范等实施所需选择
- [ ] 存量项目已检查文档覆盖情况；缺文档时已主动按规则补齐当前实现，并向用户报告合理性、缺陷、代码依据、影响和建议，未把未经确认的建议写成现有设计
- [ ] 未决问题已按模块内 §11、跨模块总文档 §7 归位；影响实现或测试预期的问题标为实施阻塞项

## B. 文档结构与依赖

- [ ] 总文档及业务模块文档位于 `design-doc/index.md`、`design-doc/{name}/index.md`，必需章节齐全
- [ ] 可选章节仅在适用时出现；省略后保留固定编号，没有空标题或占位内容
- [ ] 按业务职责划分模块，索引、文档与依赖图一致；新设计无环且被依赖方优先，存量补档如实记录现存环并标明整改需求，未伪造拓扑顺序或检查通过结论
- [ ] 依赖说明包含可用的相对链接及章节引用，共享数据结构只在定义方模块维护；模块没有未声明的依赖
- [ ] 已按项目可用工具或模板完成格式检查，流程图语法和文档链接已核对

## C. 方案与实施计划

- [ ] 当前范围内每项需求都在现有计划或验收条目中对应到设计章节及 UT/IT 用例；不能自动化验证的约束已说明核验方法和原因，未以章节齐全代替需求覆盖
- [ ] 业务规则、判定条件、行为预期及适用的性能或时限要求明确，影响实施的答案已写入文档而非仅留在聊天中
- [ ] 新增或变更接口的签名、参数、返回值及错误行为完整，数据结构和核心 Mermaid 流程一致
- [ ] 接口输入范围、空值约束及适用的鉴权、权限、幂等性契约明确；并发、事务、重试、超时和降级等适用场景已有处理策略及对应测试
- [ ] 目标运行环境、版本和兼容范围明确；涉及的配置项、默认值及迁移兼容策略已在相应章节写明
- [ ] 模块影响、兼容性、风险与回滚说明符合本次变更，验收标准能判断结果
- [ ] 实施计划逐单元包含实现、设计章节、测试用例编号及运行验证，通过后进入下一步；没有把全部测试推迟到最后

## D. 按需设计

- [ ] 涉及用户交互时，已有设计资源或经确认的线框图、组件层次、交互状态及状态归属齐全
- [ ] 涉及用户交互时，已按“已有组件 → 项目组件工具集 → 开源组件 → 自研”选型，并记录来源；只有前三项不能满足需求时才建议自研
- [ ] 涉及用户交互时，总文档视觉规范按模板填写，色值、语义映射、字体、间距、圆角与阴影完整
- [ ] 涉及数据库时，ER 图、表结构、索引和迁移说明齐全
- [ ] 涉及外部服务时，`external-service/` 仅记录 API 契约，无实施状态、测试设计、实施计划或验收；本地调用逻辑归调用方业务模块

## E. 单元测试设计

- [ ] 已确定测试框架、运行命令、工作目录、测试文件路径及 mock 策略；已有项目沿用现有测试组织方式
- [ ] 每个业务模块 §8.2 均有可直接实施的具体用例，包含场景、输入、预期结果、类型和状态，覆盖 happy path / boundary / error，未把测试设计留给 fullstack
- [ ] 单元用例编号符合 `{module-name}-UT-{NNN}`，项目内唯一；旧编号未重排，新增用例追加编号，参数化用例有明确参数实例
- [ ] 需要项目内集成验证时，§8.4 已定义具体 IT 用例、真实调用与 mock 边界、运行条件、文件及命令，并在实施计划与验收中引用；不适用时未新增集成要求
- [ ] 涉及外部 API 调用时，本地参数组装、响应及错误处理的测试在调用方模块中定义，以 mock 验证；未要求单元测试验证远端可用性
- [ ] 最终报告路径声明为项目级唯一的 `tests/test-report.md`，未规划模块级独立报告

## F. 状态与交付边界

- [ ] 新设计、迭代、补档和修复中的设计调整均只描述当前有效方案；失效内容和已解决未决项已清理，没有旧方案回顾、新旧对照、版本沿革、变更日志或修复记录，历史仅由 Git 保存
- [ ] 总文档及本次涉及模块的设计时间已更新；实施状态和实施时间只在业务模块文档维护
- [ ] 迭代时保留仍有效且未变更条目的当前状态，变更条目按主规则标为“待迭代”并附日期；时间与状态字段没有累积历史轨迹
- [ ] 影响行为、契约、测试或验收的变更已同步将模块头部标为待迭代，未出现头部已完成而相关条目未完成；纯文字或排版修正未误重置状态
- [ ] 存量补档未把代码存在当成测试通过，未臆造历史时间或验证结果；预期行为不明、依赖环等阻塞项已说明，未将补档完成等同于具备实施条件
- [ ] 交接说明文档路径、本次 scope、可实施结论或阻塞原因；原请求含实施且具备条件时返回 fullstack 继续，纯设计请求在交付后结束
- [ ] 没有直接修改业务代码、跨项目设计、自动提交或生成 PR；文档不包含完整业务函数、超过 15 行的连续业务代码或估时
