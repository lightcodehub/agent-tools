# program 输出自检清单

在输出设计文档前，逐项确认：

## A. 结构完整性

- [ ] 已输出总设计文档（`design-doc/index.md`），包含所有固定章节（视觉规范按需出现）
- [ ] 已为每个模块输出独立文档（`design-doc/{name}/index.md`），包含 1-11 所有一级章节
- [ ] 总文档包含模块索引表和完整依赖图
- [ ] 依赖图为有向无环图（DAG），已通过循环依赖检测
- [ ] 模块按业务逻辑划分，不以技术分层（controller/service/repository）为模块边界
- [ ] 涉及数据库时，已包含数据库设计；不涉及时已省略该子章节
- [ ] 涉及用户交互时，已包含用户交互设计；不涉及时已省略该子章节
- [ ] 不涉及的"按需出现"子章节已整段省略，没有留空标题或占位符

## B. 代码证据

- [ ] 设计结论均有代码阅读依据，无凭空臆测
- [ ] 已识别项目测试框架和测试目录约定（作为内部依据）
- [ ] 已识别用户交互组件目录和复用入口（作为内部依据）

## C. 方案质量

- [ ] 方案是模块化拆分，不是大段实现描述
- [ ] API 定义完整，新增/变更接口都已列出
- [ ] 核心流程已用 Mermaid 流程图表达
- [ ] 用户交互设计是结构化、组件化的
- [ ] 状态归属与组件组合关系已说明

## D. 组件复用优先级

- [ ] 已先检查项目内已有组件
- [ ] 已先检查项目内用户交互组件工具集
- [ ] 只有在项目内无可复用方案时，才引用开源组件
- [ ] 只有在前两者都不满足时，才建议自研实现
- [ ] 文档中明确写出了组件来源

## E. 数据库设计（按需）

- [ ] 已提供 ER 图（Mermaid）
- [ ] 已列出表结构
- [ ] 已列出索引设计
- [ ] 已说明迁移策略

## F. 单元测试设计

- [ ] 单元测试基于当前项目已有测试框架
- [ ] 覆盖 happy path
- [ ] 覆盖 boundary
- [ ] 覆盖 error
- [ ] 已规划测试文件
- [ ] 没有重新发明测试体系

## G. 输出边界

- [ ] 没有贴完整函数实现
- [ ] 没有超过 15 行的连续业务代码
- [ ] 没有估时
- [ ] 没有无代码证据的臆测
- [ ] 未确认内容已进入未决问题
- [ ] 不以技术分层当业务模块
- [ ] 不跨项目设计

## H. 模块化检查

- [ ] 每个模块文档的依赖说明包含指向依赖模块文档具体章节的相对链接
- [ ] 每个模块文档自包含，可独立阅读实施（不含对模块外部的隐性假设）
- [ ] 跨模块共享数据结构已在总文档中列出，模块文档不重复定义
- [ ] 文件命名符合约定：`design-doc/index.md` + `design-doc/{name}/index.md`
- [ ] 依赖图节点与模块索引表一致，无遗漏无多余
- [ ] 模块按拓扑序排列（被依赖的排在前面）
