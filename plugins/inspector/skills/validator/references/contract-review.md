# 设计、调用与断言的独立核验

validator 对本次交付版本的核验结论负责。自行从范围内的设计条款取得预期，追到生产调用、可达分支和持久测试的具体断言。architect 的自查和 developer 的自测回执用于定位证据，核验由当前独立会话完成。

## 取证步骤

1. 先按[模块依赖与影响](scoped-reading.md#索引与范围)定范围，再调用 architect 的 `scripts/audit_design.py --root "$design_dir" --view inventory`。日常迭代对变更模块及受影响模块分别传 `--file 相对路径`，已排除的候选不加入底表。全仓核查传 `--all`。底表记录受审文档和已解析契约目标的内容哈希。随后运行本 skill 的 `scripts/contract_review.py --root "$design_dir" --inventory "$inventory" --view all`，取得逐文件、章节和契约行的待核清单。大结果按文件读取。模板工具不可用时用当前宿主等价提取，保留同样的覆盖范围。普通复核也执行适用核查，只读时在内存处理。
2. **先核对依赖表。** 按总设计和真实装配确定使用方生产路径，运行同一命令的 `--view bindings`，用可重复的 `--consumer 模块名=项目相对路径` 传入受审使用方；共享装配不在模块目录时一并传入。每行对齐用途、每个声明的接口或类型、使用方实际绑定及测试观察。命中只供定位；未命中时沿装配、别名或转发追到实际符号，并检查同一提供方的其他操作。按行记录真实位置，在继续其他章节前用 `--view bindings --decisions 决策文件` 对账，未对账的行继续核实。证据确实不可取得时记录具体边界。仅核查文档也执行此步。
3. **先审内容，再汇总运行与格式结果。** 用 `--view priority` 找出需要优先反查的项目：分别逐行打开使用符号与目标符号不一致的契约、多个功能共用的入口，以及带限定条件的行为。每项均读目标定义正文、实际调用方及其使用的实现；接口注入沿装配点查具体方法。共享入口可能正确，须以每行实际行为区分。将已证实的错配及双方位置写入发现，不能仅附原始索引。
4. 对“仅在……时执行”等限定条款，列出设计允许的触发集合，与代码中所有能到达该行为的分支双向比较。若调用方依据共享状态、返回码、错误类型或分类器做决定，继续追查生产方在哪些输入下生成它，逐类核实实际可达的后续动作。将多出的触发、漏掉的触发或排除条件与具体源码和相关测试对齐。优先项只是起点，仍须覆盖其余适用条款。
5. 核查场景归属时用 `--view cases` 取得本版逐行 ID、设计落点及反向线索；以 `--view cases --decisions 决策文件` 对账。完整核查覆盖每个实际场景行。前向和反向相同仍须区分参数分支，不能凭号段推定覆盖。先在 §8.2 逐行打开本行或对应组头的功能/共享规则链接，对照实际断言核准归属；渲染后复核整条调用及输入、按键、输出值的显示边界。按用例与实例读持久测试：记录输入前置、真实执行的生产分支、替身边界与最终断言。对每个可独立失效的要求，确定违反要求时哪条断言会失败。有条件执行受控对照时保存结果；测试环境不可用时仍完成可静态验证的调用和断言核查，区分静态发现与执行限制。
6. **交付前核对遗漏。** 每份受审文档都有文件级条目，包含模板差异和待判定的条件项。正文为空或缺少章节时也要给出有依据的偏差或未核实原因。独立解析本版全文，先核实底表中每份文档的 `rendering.parser` 和实际解析范围。将渲染节点与原文、业务含义对应；同类失真逐处定位到文件、行及相应单元格，明确合法对照。使用其他目标方言时按其渲染器复核。来自 `object_findings` 的格式条目按文件和行号核对后，在审查发现中列明确认的偏差；同类项可合并并保留全部位置。不能以文件级记录覆盖对象级发现。未完成核实的场景归属或交互字面值列为未核验，整稿格式通过须有覆盖全部适用项的依据。逐项归集符合、偏差、不适用和未核实的理由；同一可观察断言可共享证据。可写时将明细放在本轮 artifacts，用 `--decisions` 对账；输入为 JSON 对象，`inventory_sha256` 取自该底表的 `--view summary` 输出，`decisions` 为决策数组。数组中每组含具体清单 `items`、`status`、`basis` 以及已核实项的 `evidence` 位置（实现/调用点、断言及必要的运行证据）。旧版无指纹底表须重建。文档、契约目标或全仓文档集合变化时，重新盘点、复核受影响证据，并用新版底表登记决策。对账退出 0 仅表示所有条目都有处置记录，结论须区分符合、偏差与未核实。对照余项继续取证；真正受阻的项写明缺少什么，不能把可查源码笼统标为环境受阻。仅对本版有独立依据的条款给出肯定结论。报告 E 节列明发现与归属，F 节据此判定。设计契约或说明错误交 architect；实现或已设计的测试断言缺陷交 developer。两方按原有审核与授权边界处理。
