# 验证交付检查项

按实际入口核对。普通复核使用“共同检查”和“就地复核”；独立验收使用“共同检查”和“独立验收”。严格只读时只在聊天交付。

## 共同检查

- [ ] 已按模板核对范围内文件头的字段、顺序和取值；归属链接的可见名称与目标标题对应，链接直达正确的首页。
- [ ] §8.2 每个场景可从本行或所属组头跳到与断言相符的功能或共享规则；完整命令、参数、按键及预期字面值已经按渲染节点逐项核实。
- [ ] 已读取最终文件的 Markdown 渲染结果，核实正文与表格中的技术字面值、链接及格式边界；结论注明未覆盖范围。
- [ ] 依赖表已按使用方生产路径逐行对账，未命中项已追踪实际装配和同提供方操作。已独立读取交付版本的逐对象格式结果，逐条核实并定位偏差。文档符合性、契约与断言偏差、业务测试执行结果分别给出。

- [ ] 日常迭代已按变化契约核对必要依赖与受影响调用方，包括未改动的模块；核查范围有实际使用关系或行为传播依据。

- [ ] 已执行[逐项内容核验](contract-review.md)，底表与证据决策对应当前快照，每份文档均有文件级核查记录。按契约行和行为条件核实设计落点、生产调用、触发来源及持久测试断言。语义错配有双方依据，执行限制与仍可静态核实的事项分别处理。

- [ ] 范围、基线、源码和配置可定位。按设计列出应验行为，再读受审代码、测试正文及必要调用链；没有用开发结论、文件哈希或绿测替代契约审查。
- [ ] 已对照模块边界、功能行为与调用方，检查返回值、失败状态、依赖写回及替身边界。对有疑点而现有断言无法区分的行为，已提供最小复现或明确证据不足。发现有位置、触发条件、依据、影响和阻断判定。
- [ ] 从契约反查关键边界，再从设计实例核对执行与断言；若漏掉某一校验仍能全绿，指出未被区分的行为。设计缺项归 architect，已设计但漏测归 developer。前置条件成立，辅助源码确有调用，真实集成未被替身绕过。多入口功能从源码逐个反查入口、模式及断言，避免把同组或共用 ID 的结果推广到其他入口或真实下游。按要求执行完整单元回归、本范围集成与适用构建/人工核验；受限执行及证据缺口如实记录。
- [ ] UT/IT 分别盘点和归因。跳过、缺失、未执行及重试均未冒充通过；正常、历史、负向结果分开。重要防护对照未修改用户工作区的实现与持久测试。
- [ ] 允许执行时使用自己的 run-id，数据、驱动器和产物位置合规；核对用途、位置、格式、引用和 Git 忽略/索引，无变相入库。退出或中断后仅回收本轮资源，说明保留策略。
- [ ] 总体设计的目标、模块边界、约束和 §5 公共约定与本次实现一致；适用的视觉、外部接口及模块共享契约已定向核对。受审功能的 API 名称均能直达设计中的签名定义。设计正文不反引业务源码，实际调用与断言位置在验收证据中核实；函数定义的简介、参数、返回、错误完整且与实现相符。公共代码规范分别核验三列八项、依据与层级；未因无日志或无捕获包装误报。文档核验包含受影响的存量正文、技术字面值与实际状态。
- [ ] 不修改业务、持久测试、预期、依赖或 Git 索引。实现与测试缺陷交 developer，设计问题交 architect；仅验证不授权修复、提交或发布。

- [ ] 本次范围内各文档已按适用模板核对必需字段和定位，按项目依据核实内容；结论涵盖实际偏差和未核实项。

- [ ] 对外契约变化已对照用户确认的支持基线、旧客户端的使用方式、新服务的实际行为和测试断言，退役项已核对其他受支持调用方。

## 就地复核

- [ ] 已确认用户明确只要复核；无论会话是否干净均就地检查，未启动子代理，交付本轮观察及“未执行独立验收”。未创建或覆盖规范报告、回写设计状态或沿用旧结论；未将 UT/IT 结果作为正式技术结论。

## 独立验收

- [ ] 已说明实际隔离依据：参与实现或来源不明的会话（含直接调用 validator）有实际派生记录、不继承开发对话的依据及对应快照的返回结论；已确认干净的会话直接执行，无重复派生；修后版本由新子代理重新审读和执行。新的 run-id 或代理名本身不证明隔离。无法启动、隔离不明或未返回结论时，父会话未改写报告、状态或自行改为就地复核。
- [ ] 以本次范围判定技术结论：阻断失败优先；未知回归经过调查仍无法归因则证据不足。审查实施计划时反查每步用例依赖的行为从哪一步可用。区分计划是否可行和历史是否执行；没有同版步骤证据时，不以最终回归补证或代改 §9。单元或集成全绿都不替代逐项验收；已证实的当前事实矛盾未被当作排版问题放行。
- [ ] 允许写入时整体重建唯一报告，表头校验覆盖 A.2、适用的 B.2、E、F，合并列后名称链接及各条未满足项的责任归属可核实。报告包括失败或执行受阻的运行。A/B 各用本轮实际实例与命令（无 IT 且盘点完整才省略 B）；C 单列历史/负向，D 说明核验与限制，E/F 记录发现和逐项依据。仅保留最小诊断摘要。
- [ ] §9 和实施时间未改；§8 自测日期保留同版有效值，缺失时取同版自测记录正文的带时区完成时间，无据注明未知。§10 与模块头部按实际证据更新，部分范围通过未标整个模块完成。检查“仍须验证”所指版本、环境及用例，区分已过期的待办、真实证据缺口与有触发条件的回归要求；矛盾或证据不足时分别说明依据。读回所有本轮写入文档的最终文本，正文、字面值、表格、状态与聊天结论一致。
