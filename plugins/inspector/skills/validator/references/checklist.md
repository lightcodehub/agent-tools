# 验证交付自检清单

按 SKILL.md、测试管理规范和报告规则核对。允许写入时，验证失败或不完整仍须输出真实报告；用户明确只读则在聊天说明结果及报告未更新；不适用项必须有依据。

## 报告一致性

- [ ] 唯一报告位于 `tests/test-report.md`，使用 `assets/test-report.md`，标题在第一行，文件头为 Markdown 信息表，章节齐全
- [ ] 只有完整盘点确认项目无设计及实际集成用例时才省略 B 节并标不适用，未把未执行或盘点不完整当作不适用
- [ ] A、B 节正常结果基于同一轮验证重建，记录命令、执行范围、退出码和环境信息，未拼接历史通过结果
- [ ] 重试按同一源码、配置及范围的最后一次尝试判定，先前失败仍有记录；中断或未启动未借用此前通过结果，源码或配置变更未拼接旧轮结果
- [ ] 报告覆盖已盘点的设计用例及实际测试：匹配项使用设计编号，设计外历史测试用文件路径、完整测试名及参数标识识别，无重复计数
- [ ] 参数实例逐项对应源码与实际证据；缺失和未运行实例纳入规范统计，框架方法数未代替实例数，未声称日志含其实际未记录的逐参数结果
- [ ] 单元、集成分别盘点，类别总数与各模块明细、五类结果之和一致；不完整时标明已知数量和未知范围，未编造总数或通过率，未合并两类统计
- [ ] 用例结果、各类别模块状态、类别状态及通过率遵循主规则；跳过、零用例和未完成执行未误判为 PASS，启动或运行错误如实记录
- [ ] 覆盖率来自工具真实输出，不可用时已说明；JUnit、JSON 等原始结果没有替代 Markdown 报告

## 范围、审查与独立验证

- [ ] 已确定需求、设计、scope、比较基线与源码/配置快照；没有用 developer 的自测结论代替独立执行
- [ ] 已在 validator 阶段实际读取本次实现、测试和必要调用链；同上下文交接未用编写记忆或仅计算哈希替代审查，发现有位置、触发条件、依据、影响和阻断判定；未把无证据疑点当缺陷
- [ ] 前置断言、测试发现、参数实例、辅助源码调用和替身边界真实，未复制业务逻辑自证或 mock 掉关键组合
- [ ] 正常验收已运行完整单元回归、范围内设计 IT 及必要构建/类型/非自动化核验；受限执行未伪称技术通过
- [ ] 负向验证按设计进行并与正常结果分开；未修改用户工作区业务代码、持久测试、预期或验收标准
- [ ] 自己的 run-id、用例数据、原始产物及只读数据集符合测试管理规范；落盘的执行驱动器/观察器在本轮 data 并已清理，数据缺失未用生产数据补位
- [ ] 实际及计划产物路径被根 /build/ 忽略、索引无 build 文件；拟提交内容按用途、位置、格式与引用逐项检查，无数据变相入库
- [ ] 失败、取消、超时及成功的本轮资源已回收或说明保留范围/期限；未删除他轮、数据集或用户文件

## 技术验收与交接

- [ ] E 节审查结果与 F 节逐项验收有可核验证据；技术结论与 UT/IT 分类统计分开，未靠测试 PASS 推导技术 PASS
- [ ] 已知阻断失败为 FAIL，必要证据不足为 INCOMPLETE；范围外问题的归因有依据，未掩盖回归
- [ ] 本次交付正文与实际实现、测试或状态矛盾时未判完整交付 PASS；格式问题按语义和执行影响判定，事实/格式修正交 developer，方案与契约调整交 architect，仅验证时未擅自改正文
- [ ] 状态回写只更新真实验证结果和当前验收状态，部分范围通过未将整个模块标为完成，未改设计规则
- [ ] 实现/测试缺陷交 developer，设计缺项交 architect；仅验证请求未自动开始修复；角色切换未重复请求已有授权
- [ ] 规范报告只有 tests/test-report.md，未创建其他审查或验收报告；只读限制下未写文件且明确报告未更新
- [ ] 如实说明执行上下文，未把同一上下文角色切换冒充多人独立复核
- [ ] 未擅自提交、推送、发布或作产品验收决定；聊天、报告、状态及清理结果一致

## 产出文档表达

- [ ] 已执行交付前文档核验，逐文件读回范围内完整相关正文（含存量未改段落），修正后复核最终文本；实际核验方式与范围有据可查，本角色写入或更新的文档已在最后写入后检查（validator 包括报告）

- [ ] 命令、路径、标识符、正则和样例字面值使用代码格式或有效链接，Markdown 解析后字符与表格结构完整，未把格式化工具通过视为语义核验
- [ ] 已逐项核对本次范围正文、代码、测试与状态；无过期的现状陈述或失效风险，范围外未完成项及明确版本的历史事实未被误改；事实同步、方案调整和验收状态按角色职责处理

- [ ] 已按文档表达规范读回成稿，正文无需聊天上下文即可理解，无对话记录、工作故事或遗留模板提示
- [ ] 结论、条件、依据与限制清楚，术语一致，语言自然精简，无重复套话或无依据的效果评价
- [ ] 表达调整未改变业务规则、文档结构、角色职责、状态或用例；必需验证证据及失败、重试事实完整保留

## 设计内容与公共约定

- [ ] 总体协作中的跨模块读取、状态变化和结果写回均有归属明确的操作契约；调用方依赖、测试和实施前提已同步，未用类型或表存在代替能力就绪
- [ ] 单元用例预期在真实可观察边界内，未以创建/投递/替身成功证明下游结果；完整业务预期由相应模块或真实集成用例覆盖，边界调整未丢需求

- [ ] 公共代码与测试约定由项目级文档集中定义，模块链接可解析；具体接口、测试路径、命令、数据准备及必要例外完整，未把引用误判为缺项
- [ ] 不适用的可选章节或子节已省略且编号稳定，实际契约与依赖未遗漏；没有空表、批量“无”或模板默认的技术选择
- [ ] 运行时失败处理与测试替身分开，成品未包含角色操作规则、填写提示或未经核实的检查声明

- [ ] Markdown 表格没有列宽填充，分隔行保留必要对齐标记；格式调整未改变链接、代码块、元数据、样例值或有语义的空白

## 总体与详细设计分层

- [ ] 新项目与存量补档遵守相同粒度；仅确有独立职责、公开契约与依赖边界的单文件模块可在总文档注明文件名，未以可导入为由拆出伪模块
- [ ] 模块详细设计承接必要实现映射，新项目规划与存量事实分清；具体位置未因下沉而遗漏，公共约定的配置、命令和文档链接仍可执行、可解析

- [ ] 总文档给出整体目标、总体方案和代码架构，背景未被函数缺陷清单替代；局部任务未覆盖或扩写无关项目设计
- [ ] 总文档以模块、层、包和组织边界表达架构，依赖图使用模块名称；内部文件、类、函数入口及源码证据在模块详细设计，未将存量文件清单当作架构
- [ ] 项目约束有依据且与设计选择、工程约定分开；本次范围的实现和验收有对应约束及证据
- [ ] 公共约定及适用视觉资料引用有效，读取后内容完整；已有有效设计未因章节编号不同被误报缺项

## 公共代码规范一致性

- [ ] 类型行未列记录/数据对象的实现方式，即使多个模块都使用也仅引用模块契约；注释行在缺乏统一惯例时明确缺口，核验范围不超过实际证据

- [ ] 结构与语义分开核验：单模块业务事实未冒充公共规则，局部类型/依赖实现方式已下沉；源码惯例只适用于有一致证据的范围，未将少数注释样例推广到全项目

- [ ] §5.1 使用固定三列和八行，规范项名称与顺序和模板一致；未删减、合并、改名或用段落代替，已有规范引用仍保留相应行
- [ ] 八类均有实际约定或有效引用、适用范围与核验方式；无机制时写明事实和边界，未知未冒充不存在，没有空项或仅写“不适用”
- [ ] 新项目采用的规范与工具规划明确；存量成文规则、配置与源码归纳有依据并区分，未把局部实现、缺陷或建议提升为全项目规范
- [ ] 表内只保留公共编码原则；字段取值、参数校验、构造器行为、具体异常/状态/恢复流程和事件定义在模块文档，引用有效且未因下沉丢失必要信息
- [ ] 核验方法对应检查对象，命令与配置真实存在；未把单元测试通过当作风格或注释检查，也未为填表引入工具或默认业务规则
- [ ] 无日志、自然异常传播或无资源机制已在对应行交代，没有因固定八行新增不必要代码；实际需要的恢复、资源回收、必要日志和信息保护未被省略

## 读取范围与证据

- [ ] 依赖文档按所用契约的实际章节边界读取，未因文件短而展开其它契约；补读已有内容有未加载、变化、截断或上下文缺失等依据

- [ ] 未因阶段切换或自检重读已在上下文且未变的共同规则；有效现有文档定点更新未加载无关模板章节，必要指令与最终正文核验未省略

- [ ] 依赖与无环结论注明实际核验范围；仅检索索引或检查子图时未宣称全项目源码已核对，未覆盖范围外已有有效结论

- [ ] 以总设计索引和任务范围定位目标，仅加载相关模块/契约/实现及必要上下文；没有把依赖图当成必须递归阅读全文的清单
- [ ] 接口、共享行为或配置变化时已核对受影响调用方；索引失效、新依赖或失败证据已触发必要扩展，没有为少读而遗漏影响面
- [ ] 本轮实际审读范围与结论一致，未用摘要/哈希代替关键行为核对；回归执行范围未因减少上下文而缩水
