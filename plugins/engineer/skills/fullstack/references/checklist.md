# 实现交付自检清单

本次实现、测试、报告及适用的内部 skill 更新完成后，向用户交付前核对。以 `SKILL.md`、设计文档和用户授权范围为依据，本清单不另设代码规范。

适用项满足后标记通过；条件不成立的项目注明“不适用”及原因。未满足项保留并说明原因，不把失败或阻塞包装成完成；已进入测试验证但未能完成时，仍输出本轮真实报告。

## A. 本次实施范围与设计

- [ ] 已明确本次 scope；范围内设计要求及验收已满足，没有要求补做范围外未实现模块
- [ ] 设计不足时已在同一任务进入 architect 补齐并重新校验；未要求用户重复发起同一需求，未因“直接实现”或少量改动绕过必要设计
- [ ] 已检查本次范围及必要依赖的未决问题和依赖环；未把补档落盘或实施状态当作设计就绪，也未用范围外问题扩大任务
- [ ] 按本次 scope 及必要依赖子图排序，未让无关模块的环阻塞任务；依赖就绪性已同时核对模块头部、相关条目和实际接口
- [ ] 编码前已校验业务规则、接口、边界、环境兼容约束及具体测试用例；设计缺失先由 architect 补全文档并重新校验，未凭聊天答案绕过文档直接编码
- [ ] 本次改动的 API、数据结构与关键流程符合设计；共享结构在定义方与引用方之间一致
- [ ] 设计偏差、未决问题及新增依赖已按主规则处理并回报；未解决的阻塞项未被标为完成
- [ ] 已利用宿主可用 skill、已有发现结果或当前任务线索定位相关库，完整读取匹配的 skill 及 API 文档；没有 skill 时也已检查文档、接口和已有调用
- [ ] 未在编码任务中自动运行项目级发现注册；未因未注册而忽略已定位库的现有能力
- [ ] 复用选择有依据，新增实现限于已确认的能力缺口；未因自动触发未命中或发现入口缺失而重复实现已有能力

## B. 代码与运行验证

- [ ] 本次改动已完成适用的编译、类型检查或运行验证，有实际结果；无法执行的检查已说明原因
- [ ] 命名、结构、注释及错误处理符合总设计文档 §3 和项目既有规范
- [ ] 本次交付没有未完成的占位实现、伪代码或遗留调试输出；未因检查而清理范围外历史 TODO 或合法日志
- [ ] 设计要求的异常、边界处理和关键路径日志已就位；涉及外部调用时，超时及失败处理符合调用方设计
- [ ] 涉及用户交互时，组件复用、语义颜色、亮暗主题及样式常量符合设计视觉规范

## C. 测试执行

- [ ] 未为通过测试删除失败用例、弱化断言、篡改预期、缩小执行范围或 mock 掉被测逻辑；合法测试调整有需求、设计或错误依据，跳过和未运行未计作通过
- [ ] 本次实施范围内的设计用例已逐条实现并实际运行通过，编号及参数实例可追踪；每个独立单元验证后才进入下一单元
- [ ] 涉及外部 API 时，以 mock 验证本地调用逻辑，用例和结果归调用方业务模块；未把远端可用性作为单元测试门槛
- [ ] 设计要求的范围内集成验收已验证真实调用；尚未就绪的依赖和未完成的集成项已说明，未用 mock 结果冒充真实集成结果
- [ ] 项目内集成验证按设计 §8.4 的 IT 用例执行，不在验收时临时增加要求；结果单独记录，未混入单元测试统计
- [ ] 单元与集成优先分别执行；混跑时依据结构化结果归因，未因 IT 失败导致的非零退出码误判单元失败，无法拆分时已标明 INCOMPLETE
- [ ] 正常交付前已运行项目完整单元测试集；若失败或中断，已记录实际范围、原因及已知未运行用例
- [ ] 本次实施结论与项目报告状态分别说明；范围外未实现项未被算成本次必须实现的任务，回归失败已调查并说明

## D. 项目测试报告

- [ ] 唯一报告位于 `tests/test-report.md`，使用 `assets/test-report-template.md`，标题在第一行，文件头为 Markdown 信息表，章节齐全
- [ ] 报告整体基于同一轮验证重建，记录命令、执行范围、退出码和环境信息，未拼接历史通过结果
- [ ] 重试按同一源码、配置及范围的最后一次尝试判定，先前失败仍有记录；中断或未启动未借用此前通过结果，源码或配置变更未拼接旧轮结果
- [ ] 报告覆盖已盘点的设计用例及实际测试：匹配项使用设计编号，设计外历史测试用文件路径、完整测试名及参数标识识别，无重复计数
- [ ] 盘点完整时总数与各模块明细、五类结果之和一致；不完整时标明已知数量和未知范围，未编造项目总数或通过率
- [ ] 用例结果、模块状态、整体状态及通过率遵循主规则；跳过、零用例和未完成执行未误判为 PASS，启动或运行错误如实记录
- [ ] 覆盖率来自工具真实输出，不可用时已说明；JUnit、JSON 等原始结果没有替代 Markdown 报告

## E. 文档与内部 skill

- [ ] 设计文档只保留当前有效方案，没有修复日志、旧行为、根因分析、修复经过或前后对比；恢复既有设计的修复未被写成新的设计记录
- [ ] 本次涉及模块的步骤、用例、验收状态及实施时间与事实一致，全部验收满足后才标记模块完成；总文档未复制模块状态
- [ ] 模块头部与相关条目一致，存在待迭代、待测试或未满足验收项时未保留已完成标记
- [ ] 状态回写只更新现有条目当前值，没有追加历史轨迹；已解决的设计未决项或失效风险已由设计阶段清理，测试过程未复制到设计正文
- [ ] 涉及视觉规范落地时，其状态与实际完成情况一致
- [ ] 本次产出或修改的可复用库或工具有轻量的能力发现 skill，description 能匹配使用场景，正文指向真实入口及 API 文档；接口变化已同步，详细 API 文档未重复维护
- [ ] skill 源文件与代码同属可移动、可分发单元，文档和资源包含在发布范围内；引用按真实源位置解析，无开发机器绝对路径或未说明的工作目录假设
- [ ] 新建或迁移 skill 时已说明源位置及用户可主动执行的注册方式，未自动创建、修复或覆盖发现入口；实际验证范围已说明
- [ ] 使用脚本时已写明命令、工作目录和预期结果，已有库脚本未为目录形式而复制

## F. 改动与授权边界

- [ ] 本次改动限于用户已授权的任务；未顺手重构或修改无关文件，范围扩展已按主规则确认
- [ ] CI/CD、依赖大版本及新增依赖的处理符合主规则和用户明确指示；新增依赖已说明
- [ ] 未自动 commit、push 或创建 PR；最终交付包含改动文件、验证结果及未决事项
