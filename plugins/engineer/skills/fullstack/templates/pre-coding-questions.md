# 编码前提问模板

在读取设计文档后，如果存在以下四类缺失信息，必须使用本模板组织问题向用户提问。最多追问两轮。

## A. 需求不明确

当设计文档的业务规则、用户故事或行为预期不够清晰时：

- `{功能/模块}` 在 `{某个边界场景}` 下应该表现什么行为？（例如：用户已删除的资料能否恢复？）
- `{某个业务规则}` 的判定标准是什么？是否有例外情况？
- `{某个流程}` 的预期耗时或超时时间是多少？

## B. 接口定义不完整

当 API 的参数、返回值、错误码或鉴权信息不完整时：

- `{接口名}` 的 `{参数}` 取值范围是什么？是否允许空值？
- `{接口名}` 在 `{某种异常场景}` 下返回什么错误码和错误信息？
- `{接口名}` 是否需要鉴权？是否需要幂等性保证？

## C. 边界条件缺失

当文档未覆盖空值、极值、并发、失败重试等边界时：

- `{功能/模块}` 在输入为空或 `null` 时如何处理？
- `{功能/模块}` 在并发调用场景下是否需要锁或事务？
- `{功能/模块}` 在依赖服务（数据库/第三方 API）超时或返回错误时的降级策略是什么？

## D. 环境与兼容性

当运行环境、依赖版本或兼容性约束不明确时：

- 是否需要兼容 `{旧版本/旧数据}`？兼容策略是什么？
- 是否涉及到配置项变更？新的配置默认值是什么？
- 代码运行的目标环境是 `{Node 版本/浏览器/Android API 级别/iOS 版本}`？

## 提问格式建议

每轮提问控制在 2-4 个问题，按优先级从高到低排列。以"编码前提问（1/2）"标注轮次。

```
编码前提问（1/2）：

根据设计文档，有几个信息需要在编码前提您确认：

1. [A. 需求不明确] ...？
2. [B. 接口定义不完整] ...？
3. [C. 边界条件缺失] ...？
```
