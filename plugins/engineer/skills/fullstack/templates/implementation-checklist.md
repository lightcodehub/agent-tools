# fullstack 交付前自检清单

在输出最终结果前，逐项确认：

## A. 设计文档对齐

- [ ] 设计文档每个一级章节都有对应落地
- [ ] API 签名（路由/方法/参数/返回）与文档一致
- [ ] 数据结构字段名与类型与文档一致
- [ ] 流程图中的核心流转路径在代码中可追踪
- [ ] 设计文档中的"未决问题"已显式处理或回写

## B. 代码质量

- [ ] 代码可编译/可运行（无语法错误、类型错误）
- [ ] 命名语义化，与项目既有命名风格一致
- [ ] 函数/方法嵌套层级 ≤ 3（不含回调）
- [ ] 无 TODO、FIXME、console.log 残留等占位代码

## C. 健壮性

- [ ] 主要异常场景有 catch / 错误处理
- [ ] 关键路径有日志输出
- [ ] 边界场景（空值、极值、非法输入）有处理
- [ ] 外部依赖调用有超时或失败兜底（如适用）

## D. 测试

- [ ] 设计文档明确要求的测试用例已全部实现并运行通过
- [ ] happy path / boundary / error 三类至少各有一个用例（文档无明确要求时）
- [ ] 测试已实际运行通过（不只看代码）
- [ ] 测试报告已产出（工具原生或自定义）
- [ ] 测试报告与设计文档测试用例逐条对应

## E. 边界

- [ ] 未修改设计文档范围外的模块或文件
- [ ] 未做"顺手重构"或无关优化
- [ ] 未自动 commit / push / 创建 PR
- [ ] 涉及既有代码修改时已获得用户批准
- [ ] 未决问题已向用户回报

## F. 环境

- [ ] 未修改 CI/CD 配置
- [ ] 未升级/降级依赖的大版本号
- [ ] 新增依赖（如有）已向用户说明
