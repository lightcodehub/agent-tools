# 自测回执

每次实际执行单独记录，覆盖成功、失败、中断、超时和未启动。这是本轮运行证据，不是可提交的开发报告。

| 时点 | 必须取得的证据 |
| --- | --- |
| 执行前 | 从项目绝对根定位源码、配置、持久测试，记录比较基线、工作树改动或文件校验值、实际命令及工作目录、环境、设计用例 ID 和计划范围。为本次运行确定唯一 run-id；参数化用例须在启动前配置逐实例采证。 |
| 启动与结束 | 回执正文记录带时区的实际开始、完成时间以及退出码；未启动、未退出或无法核实的字段注明原因，不补猜，不用文件时间戳代替。 |
| 取得结果 | 单元与集成分别判读，混跑按实例证据归因。将用例 ID 与参数标识、实际结果和诊断对应。框架只给方法级结果时，用结构化事件、按实例注册或受控观察器取证；无法区分时标明证据不完整。跳过、未运行不算通过。 |
| 落盘与交接 | 原始日志、结构化结果及回执在同一个 `build/tests/runs/{run-id}/artifacts/`。运行器自行建目录时先捕获快照，再把缺失字段补到其实际目录，不另建兄弟目录。聊天仅给摘要和位置，保留至 validator 不再需要。 |

临时驱动器通过标准输入执行，或放在本轮 `data/{module}/{case-id}/`，不写在 artifacts、业务源码目录或系统临时目录（设计已明确的位置例外除外）。真实集成依赖不可用时如实记录；按设计 mock 外部 API 的单测无需真实凭据。修复或配置变化后使用新快照和新 run-id；负向验证与正常结果分开，不用无关异常证明回归。所有退出路径回收所属资源，不删他轮或只读数据集。

完成状态只依据本次实际证据：逐实例结果不足时不宣称该单元自测完成。维护本范围 §8、§9 和实施时间；撤销过期的模块头部完成标记，保留范围外状态及仍有效限制，不写 §10 或宣布验收完成。
