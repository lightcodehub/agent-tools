# 实现交付自检清单

本次实现、自测证据及适用的内部 skill 更新完成后，向用户交付前核对。以 `SKILL.md`、设计文档和用户授权范围为依据，本清单不另设代码规范。

适用项满足后标记通过；条件不成立的项目注明“不适用”及原因。未满足项保留并说明原因，不把失败或阻塞包装成完成；已进入测试验证但未能完成时，仍保留本轮自测证据并交验。

## A. 本次实施范围与设计

- [ ] 已明确本次 scope；范围内实现与自测要求已满足，独立验收状态如实说明，没有要求补做范围外未实现模块
- [ ] 设计不足时已在同一任务进入 architect 补齐并重新校验；未要求用户重复发起同一需求，未因“直接实现”或少量改动绕过必要设计
- [ ] 已检查本次范围及必要依赖的未决问题和依赖环；未把补档落盘或实施状态当作设计就绪，也未用范围外问题扩大任务
- [ ] 按本次 scope 及必要依赖子图排序，未让无关模块的环阻塞任务；依赖就绪性已同时核对模块头部、相关条目和实际接口
- [ ] 编码前已校验业务规则、接口、边界、环境兼容约束及具体测试用例；设计缺失先由 architect 补全文档并重新校验，未凭聊天答案绕过文档直接编码
- [ ] 本次改动的 API、数据结构与关键流程符合设计；共享结构在定义方与引用方之间一致
- [ ] 设计偏差、未决问题及新增依赖已按主规则处理并回报；未解决的阻塞项未被标为完成
- [ ] 已利用宿主可用 skill、已有发现结果或当前任务线索定位相关库，完整读取匹配的 skill 及 API 文档；没有 skill 时也已检查文档、接口和已有调用
- [ ] 未在编码任务中自动运行项目级发现注册；未因未注册而忽略已定位库的现有能力
- [ ] 复用选择有依据，新增实现限于已确认的能力缺口；未因自动触发未命中或发现入口缺失而重复实现已有能力

## B. 代码与运行验证

- [ ] 本次改动已完成适用的编译、类型检查或运行验证，有实际结果；无法执行的检查已说明原因
- [ ] 命名、结构、注释及错误处理符合总设计文档 §3.1（或对应代码规范章节）和项目既有规范
- [ ] 本次交付没有未完成的占位实现、伪代码或遗留调试输出；未因检查而清理范围外历史 TODO 或合法日志
- [ ] 设计要求的异常、边界处理和关键路径日志已就位；涉及外部调用时，超时及失败处理符合调用方设计
- [ ] 涉及用户交互时，组件复用、语义颜色、亮暗主题及样式常量符合设计视觉规范

## C. 测试执行

- [ ] 未为通过测试删除失败用例、弱化断言、篡改预期、缩小执行范围或 mock 掉被测逻辑；合法测试调整有需求、设计或错误依据，跳过和未运行未计作通过
- [ ] 本次实施范围内的设计用例已逐条实现并实际运行通过，编号及参数实例可追踪；未编写的测试保持待实现；参数采证在自测启动前配置，方法级成功未代替实例证据；每个独立单元验证后才进入下一单元
- [ ] 涉及外部 API 时，以 mock 验证本地调用逻辑，用例和结果归调用方业务模块；未把远端可用性作为单元测试门槛
- [ ] 设计要求的集成测试源码已实现并按可用条件自测，独立集成验收交 validator；尚未就绪的依赖和未完成的集成项已说明，未用 mock 结果冒充真实集成结果
- [ ] 项目内集成验证按设计 §8.4 的 IT 用例执行，不在验收时临时增加要求；结果单独记录，未混入单元测试统计
- [ ] 单元与集成优先分别执行；混跑时依据结构化结果归因，未因 IT 失败导致的非零退出码误判单元失败，无法拆分时已标明 INCOMPLETE
- [ ] 已逐单元运行必要自测；项目完整单元回归由 validator 独立执行；若失败或中断，已记录实际范围、原因及已知未运行用例
- [ ] 本次实施结论与单元、集成状态分别说明；范围外未实现项未被算成本次必须实现的任务，回归失败已调查并说明

## D. 自测证据与交验

- [ ] 自测命令、环境、源码/配置版本在各轮执行前记录，编号、结果和退出码保存在对应 artifacts；未用最终工作树反填历史运行版本；运行器缺失字段已补充到实际 run-id 的同一 artifacts，未另建仅存证据的运行目录；参数化实例有对应证据，失败或中断未被掩盖
- [ ] 已向 validator 交接设计、scope、变更范围、证据与限制；未覆盖或代写 `tests/test-report.md`，旧报告过期已说明
- [ ] 自测完成与技术验收分开；模块头部和 §10 完成状态由 validator 判定，缺少独立验证时未声称验收通过

## E. 文档与内部 skill

- [ ] 设计文档只保留当前有效方案，没有修复日志、旧行为、根因分析、修复经过或前后对比；恢复既有设计的修复未被写成新的设计记录
- [ ] 本次涉及模块的步骤、用例、验收状态及实施时间与事实一致，模块完成状态由 validator 在全部技术验收满足后判定；总文档未复制模块状态
- [ ] 模块头部与相关条目一致，存在待迭代、待测试或未满足验收项时未保留已完成标记
- [ ] 状态回写只更新现有条目当前值，没有追加历史轨迹；已解决的设计未决项或失效风险已由设计阶段清理，测试过程未复制到设计正文
- [ ] 涉及视觉规范落地时，其状态与实际完成情况一致
- [ ] 本次产出或修改的可复用库或工具有轻量的能力发现 skill，description 能匹配使用场景，正文指向真实入口及 API 文档；接口变化已同步，详细 API 文档未重复维护
- [ ] skill 源文件与代码同属可移动、可分发单元，文档和资源包含在发布范围内；引用按真实源位置解析，无开发机器绝对路径或未说明的工作目录假设
- [ ] 新建或迁移 skill 时已说明源位置及用户可主动执行的注册方式，未自动创建、修复或覆盖发现入口；实际验证范围已说明
- [ ] 使用脚本时已写明命令、工作目录和预期结果，已有库脚本未为目录形式而复制

## F. 改动与授权边界

- [ ] 本次改动限于用户已授权的任务；未顺手重构或修改无关文件，范围扩展已按主规则确认
- [ ] CI/CD、依赖大版本及新增依赖的处理符合主规则和用户明确指示；新增依赖已说明
- [ ] 未自动 commit、push 或创建 PR；最终交付包含改动文件、验证结果及未决事项

## G. 目录、数据与提交准入

- [ ] 已按测试管理规范从项目根解析全部路径，框架发现目录及根级配置正确；源码后缀、测试命名、模块归属和 support 实际调用满足白名单，无任务/PR/日期/批次子目录
- [ ] 执行前创建唯一 run-id；每个用例及并行参数实例数据隔离，临时程序源码和编译结果（含驱动器、证据采集脚本）在对应 data 目录，未另写系统临时目录、项目根或 artifacts
- [ ] 固定数据集路径、来源、版本、校验及缺失处理符合设计，修改先复制；未用生产数据补位
- [ ] 全部原始产物位于本轮 artifacts；位置例外确因位置被测且有设计依据，无其他仓库内产物目录
- [ ] 前置条件有真实断言，预期错误与 panic/EOF 等无关异常已区分；重要防护的负向验证有效且正常被测条件已恢复
- [ ] 交验摘要只含必要诊断信息，历史、负向与本轮自测分开；未以交验或报告引用为数据入库理由
- [ ] 已实际核验根 `.gitignore` 含 `/build/`、忽略规则覆盖 runs/datasets 的探针、实际及计划输出路径，且没有嵌套规则或否定覆盖、Git 索引无 build 文件
- [ ] 拟提交项已逐文件检查用途、位置、格式及引用，未通过移动/改名/Base64/十六进制/大字符串藏数据；生产资源未为测试重复复制
- [ ] 历史数据与产物已保留必要本地内容后取消跟踪，删除记录与失效引用已核对；无强制添加或目录笼统暂存
- [ ] 成功、失败、取消、超时资源均回收，临时数据已清理或排错保留范围/期限/清理策略明确，未删除只读数据集、其他运行或用户文件

## 产出文档表达

- [ ] 已按文档表达规范读回成稿，正文无需聊天上下文即可理解，无对话记录、工作故事或遗留模板提示
- [ ] 结论、条件、依据与限制清楚，术语一致，语言自然精简，无重复套话或无依据的效果评价
- [ ] 表达调整未改变业务规则、文档结构、角色职责、状态或用例；必需验证证据及失败、重试事实完整保留

## 设计内容与公共约定

- [ ] 公共代码与测试约定由项目级文档集中定义，模块链接可解析；具体接口、测试路径、命令、数据准备及必要例外完整，未把引用误判为缺项
- [ ] 不适用的可选章节或子节已省略且编号稳定，实际契约与依赖未遗漏；没有空表、批量“无”或模板默认的技术选择
- [ ] 运行时失败处理与测试替身分开，成品未包含角色操作规则、填写提示或未经核实的检查声明

- [ ] Markdown 表格没有列宽填充，分隔行保留必要对齐标记；格式调整未改变链接、代码块、元数据、样例值或有语义的空白
