# 开发交付检查项

所有任务核对实施、自测和状态。正常实现请求继续正式交验；用户明确限定开发或自测时，直接交付可核对的自测结果。

## 实施

- [ ] 已由总设计索引定位 scope、适用公共约定和目标功能；实施顺序只涉及必要依赖。依据真实接口、实现及自测证据判断可用性，不把共享类型或表存在等同于集成就绪。
- [ ] 每个单元有具体设计用例及可定位的当前 ID、参数实例、预期与文件路径，契约/兼容性、异常、资源或必要集成边界不明时已由 architect 补齐或标明阻塞。未用实现现状反向定义预期。
- [ ] 已核对适用的库 skill、API 与现有调用，只补真实缺口；实现可运行，符合 §5 公共代码规范、适用的视觉约束及模块契约。未擅自扩大改动、变更 CI 或升级大版本依赖。
- [ ] 新增或修改可复用库/工具时同步随库 skill 和 API 文档，不复制源或自动注册；不适用时不加载编写指南。

## 自测与状态

- [ ] 按 §9 单元落实代码和持久测试并实际运行。断言验证本层可观察行为，关键前置、替身、预期错误及真实集成边界成立。失败未靠删断言、改期望、跳过或缩小范围获得通过；修复针对原缺陷。
- [ ] 每轮都有执行前快照、命令及环境，并在同一 run-id 的 artifacts 中记录带时区的开始与完成时间、退出码、用例 ID 及参数实例结果。未启动、跳过或证据不足如实标明；修前、修后、负向及独立验证结果未混计。
- [ ] 框架从项目根定位并发现固定目录的测试，按用例隔离数据，所有退出路径只清理本轮资源。交付及已授权提交前，逐文件核对用途、位置、格式、实际调用，确认根 `/build/` 忽略有效、索引无 build 文件，也无变相嵌入的数据或原始产物；已修正失效引用、跟踪和布局。
- [ ] §8 已通过用例与 §9 已满足步骤的完成日期来自同版自测回执的完成时间，实施时间已更新；缺实现、需返工与仅待验证已区分。模块未独立验收不标完成，不写 §10 的验收结论。
- [ ] 原位更新受影响的设计、README 和 API 说明中的当前事实；读回最终段落及技术字面值，核对正文、代码、状态和限制一致。没有生成开发报告或改写 `tests/test-report.md`。

## 交验、退回与交付

- [ ] 正式交验时已新建不继承开发历史的 validator 子代理，交接范围、基线、确切快照、运行条件、阻塞及证据路径，未传推理或预定结论；实际等待该快照的结论。
- [ ] 被退回后由 developer 更新 §9 返工步骤、修复并自测。新增用例或预期需补设计时先返回 architect。修后复验用新的快照、run-id 和隔离 validator，不借用修前结论。
- [ ] 用户只要开发、自测或无法确认隔离时，交付已有证据，标明“未执行独立验收”；已启动但没有返回结论时注明“独立验收未完成”。开发会话直接调用 validator 时仍须委派独立验收；仅明确要求的复核就地执行，不更新报告或状态。
- [ ] 摘要列明实现范围、改动与风险、命令、结果和证据位置；正式交验另给出独立结论和报告位置。未自动提交、推送、建 PR 或发布。
