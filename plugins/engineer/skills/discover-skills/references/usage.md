# 发现与注册用法

由用户主动执行一次：清理所选 agent 的失效入口，扫描项目已有 skill，并立即创建缺少的项目级相对软链接。重复调用跳过已正确注册的入口，不写缓存或状态记录；不与每次编码任务绑定。

## 运行条件

需要 Python 3.9+ 和 PyYAML（`scripts/requirements.txt`）。优先使用已有可用环境；缺少依赖时按项目环境约定处理，不自动改业务依赖清单。找不到 Python 或安装受阻时报告具体原因。

脚本路径按本 skill 的真实目录定位，项目根目录显式传入：

```sh
python3 <skill-dir>/scripts/register_skills.py <project-root> --agent codex
python3 <skill-dir>/scripts/register_skills.py <project-root> --agent claude
python3 <skill-dir>/scripts/register_skills.py <project-root> --agent both
```

`--agent` 必须明确；skill 未收到目标参数时采用当前宿主。脚本默认立即清理并注册，只有用户要求预览才加 `--dry-run`。先清理再扫描，已清理入口不会残留为本轮扫描错误；无需先单独运行扫描，再让模型逐条创建链接。

- `--library-root <库目录>`：定向补扫项目外或默认排除目录中的相关库，可重复指定。
- `--exclude-dir <目录名>`：额外排除目录遍历，可重复指定。若排除目录本身是 `skills/` 下的 skill，仍读取其直接入口，不递归扫描内部资源。
- `--dry-run`：输出清理与注册计划，不创建目录或链接，也不删除链接。由于现场没有实际清理，扫描诊断仍会显示失效入口，可因此返回退出码 1。
- `scripts/scan_skills.py <project-root>`：仅需只读诊断时使用的底层扫描工具。

## 扫描与注册范围

扫描项目中的 `SKILL.md`（文件名大小写不敏感），覆盖未注册的随库 skill。默认排除 Git 数据、依赖缓存、虚拟环境、构建输出等，实际列表随结果返回；显式的 `--library-root` 可作为独立根目录扫描。

脚本解析 skill 元信息并检查正文非空，不读取所有业务源码，也不执行发现的 skill。宿主扩展字段不会仅因不在通用字段白名单中而被拒绝。无效 YAML、必填字段错误、名称与源目录不一致、正文缺失或仅含空白等会报告诊断，不注册这些来源。空正文诊断为 `body_empty`；这只是结构检查，不证明正文语义完整或其指令可执行。

标准 skill 入口和 `skills/` 中的软链接会解析到真实文件去重；任意业务目录链接不自动递归跟随。需要扫描的链接库应通过 `--library-root` 指定。新建注册的真实源必须在显式扫描根目录内；已有正确入口即使指向根目录外也保持 unchanged，但不会据此自动注册给尚无入口的其他平台。

脚本只检查文件系统，不查询宿主已安装插件或会话 skill 列表。插件源码中的 skill 属于扫描候选，即使该插件另有已安装版本，也不会自动推断应跳过；用户可通过扫描范围和 `--exclude-dir` 避免不需要的源码注册。

目标目录：

| agent | 项目入口 |
| --- | --- |
| codex | `<project>/.agents/skills/<name>` |
| claude | `<project>/.claude/skills/<name>` |
| both | 分别处理以上两种入口 |

只创建项目内入口；若目标父目录通过软链接指向项目外，报告错误，不写入外部目录。不创建用户全局入口。入口源文件始终保留原处，不复制内容。

## 幂等与冲突

| 情况 | 处理 |
| --- | --- |
| 有效来源唯一，目标入口不存在 | 自动创建相对软链接，并验证解析结果 |
| 入口已解析到已发现的同名源，包括直接存放的原始 skill 目录 | 优先判为 unchanged，即使还有同名候选或该源在扫描根目录外，也不重建、不改时间戳 |
| 目标尚无入口且同名对应多个真实源 | conflict，不猜测来源，也不把另一 agent 的入口选择自动复制过来 |
| 入口是其他文件、目录或指向其他来源的链接 | conflict，保留原内容 |
| 直接入口软链接的目标不存在、循环、不是目录或缺失 SKILL.md 文件 | removed，仅删除链接本身，记录原目标；即使没有替代来源也清理 |
| 链接可解析，但 SKILL.md 的 YAML、元信息、正文或文件数量存在问题 | 保留链接并报告诊断，不能因文档错误删除入口；不为此来源创建新入口 |
| 读取或删除权限不足 | error，保留无法确认或无法删除的条目，不视为失效 |
| 需要新建入口，但来源不在显式扫描根目录内 | skipped，提示显式指定库根目录 |
| 创建目录或链接失败 | error，说明具体原因 |

清理仅限所选 agent 发现目录的直接非隐藏软链接条目，不处理发现目录本身的断链，不递归删除目标或库内资源。清理前再次核对链接身份和失效状态；条目发生变化时保留并报告。根据输出中的 entry 和 old_target 可重建被移除的链接。

冲突不阻止其他无冲突候选注册。整体项目迁移且相对结构保持不变时，入口继续有效；只迁移源库时，旧断链会被移除，再为扫描到的唯一有效来源注册新入口。该过程不通过旧名字猜测源库的历史身份，不会覆盖仍有效的其他来源。

## 输出与验证

JSON 返回扫描清单、范围、排除项、诊断及 `registration`：

- `actions`：入口、源路径及状态：removed、created、unchanged、would_remove、would_create、conflict、skipped、error。清理项附 old_target 和 reason。预览按执行顺序模拟入口；多个 agent 共用目录时只计划创建一次，后续 unchanged 带 `projected: true`，表示复用本轮此前的计划结果，不表示链接已落盘。
- `counts`：按状态汇总。即使没有可注册来源，也可能包含残留入口的清理记录；没有任何动作时为空。
- `scan_complete`：只表示声明扫描策略内未出现诊断错误，不代表已扫描全部外部依赖。
- `ok`：清理与扫描无错误，且注册没有冲突、跳过或错误。部分失败仍保留已完成的清理及成功创建的链接，并返回未完成项。
- 退出码：0 成功；1 存在扫描错误、冲突或未完成项；2 参数或依赖问题。

本地路径正确不等于当前会话已重新加载 skill。能查宿主的 skill 列表时可进一步核对；否则只报告已验证链接。调用者在看到成功或明确错误后结束，不轮询、不重复执行直到状态变化。

`SKILL.md` 的 `disable-model-invocation: true` 用于 Claude Code，`agents/openai.yaml` 的 `allow_implicit_invocation: false` 用于 Codex；它们落实用户主动执行的选择，不应因通用字段校验器报错而删除。
