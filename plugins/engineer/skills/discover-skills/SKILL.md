# 发现并注册项目 skill

仅在用户主动调用或明确要求发现、注册项目 skill 时执行；不在开发任务开始时自动调用。

## 执行

1. 确定项目根目录和目标 agent。用户指定的路径、agent 优先；未指定路径时使用当前项目根目录，未指定 agent 时使用当前宿主（Codex 对应 `codex`，Claude Code 对应 `claude`）。只有用户要求同时支持两者时选择 `both`；无法确定宿主时询问目标，不自行写入所有平台目录。
2. 读取 `references/usage.md`。使用本 skill 真实目录下的 `scripts/register_skills.py`，执行一次清理、扫描与注册：

   ```sh
   python3 <skill-dir>/scripts/register_skills.py <project-root> --agent codex
   ```

   将 agent 替换为已确定的值。用户指定额外库时加 `--library-root <库路径>`；仅当用户要求预览时加 `--dry-run`。正常调用直接创建链接，不额外要求逐条确认。
3. 脚本先清理所选 agent 项目 skill 目录中直接挂载的失效软链接：目标不存在、链接循环、目标不是目录或已无可用的 SKILL.md 文件。只 unlink 入口本身；可解析但 YAML 错误或正文为空的链接、普通文件和目录保留，权限错误不能当成失效依据。再扫描已有 skill 并按真实源路径去重；元信息合法且正文非空的唯一来源才可创建入口，正文缺失报告 `body_empty`。
4. 已有正确入口优先跳过，来源位于项目外或还有同名候选也不影响保留。需要新建而同名来源不唯一时才报告选择冲突；指向其他有效来源的入口也保留，不强行覆盖。返回清理、新增、已存在、冲突、跳过和失败数量，以及清理路径、原链接目标和原因；没有 skill 时也报告是否清理了残留入口。创建结果经过路径解析验证，但除非实际检查宿主 skill 列表，不宣称当前会话已重新加载。

## 范围

- 只处理指定项目及显式补充的库；Codex 入口为 `<project>/.agents/skills/`，Claude Code 入口为 `<project>/.claude/skills/`，不写用户全局目录。
- 清理仅限所选发现目录的直接软链接条目，不递归清理库内资源，不删除目标代码，不修改未选平台的独立目录；目标父目录断链或指向项目外时报告错误。
- 不执行发现的 skill，不修改其内容，不建立副本或注册状态文件。幂等性依靠已有链接与真实源路径判断；用户选择合适时机调用，不做监控、定时或编码前自动重扫。
- 部分扫描失败时保留诊断，合法且无冲突的来源仍可注册。退出码非零时报告未完成项，不循环重试。
- Python 或 PyYAML 缺失时按环境约定处理，无法运行则报告具体阻塞；不把缺少运行条件当作无可发现 skill。
