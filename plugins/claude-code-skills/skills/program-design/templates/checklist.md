# program-design 输出自检清单

在输出设计文档前，逐项确认：

## A. 结构完整性

- [ ] 文档包含 1-10 所有一级章节
- [ ] `4. 方案设计` 至少包含：模块拆分、核心流程、API 定义、数据结构
- [ ] 涉及数据库时，已包含数据库设计
- [ ] 涉及前端 UI 时，已包含前端组件设计
- [ ] 已包含单元测试设计

## B. 代码证据

- [ ] `3. 现状与代码证据` 引用了真实文件路径
- [ ] 已列出关键符号和行号范围
- [ ] 已识别当前项目已有单元测试框架
- [ ] 已识别当前项目测试目录/命名约定
- [ ] 已识别项目内已有组件目录
- [ ] 已识别组件化工具集中存放位置

## C. 方案质量

- [ ] 方案是模块化拆分，不是大段实现描述
- [ ] API 定义完整，新增/变更接口都已列出
- [ ] 核心流程已用 Mermaid 流程图表达
- [ ] 前端设计是结构化、组件化的
- [ ] 状态归属与组件组合关系已说明

## D. 组件复用优先级

- [ ] 已先检查项目内已有组件
- [ ] 已先检查组件化工具集中存放位置
- [ ] 只有在项目内无可复用方案时，才引用开源组件
- [ ] 只有在前两者都不满足时，才建议自研实现
- [ ] 文档中明确写出了组件来源

## E. 数据库设计（按需）

- [ ] 已提供 ER 图（Mermaid）
- [ ] 已列出表结构
- [ ] 已列出索引设计
- [ ] 已说明迁移策略

## F. 单元测试设计

- [ ] 单元测试基于当前项目已有测试框架
- [ ] 覆盖 happy path
- [ ] 覆盖 boundary
- [ ] 覆盖 error
- [ ] 已规划测试文件
- [ ] 没有重新发明测试体系

## G. 输出边界

- [ ] 没有贴完整函数实现
- [ ] 没有超过 15 行的连续业务代码
- [ ] 没有估时
- [ ] 没有无代码证据的臆测
- [ ] 未确认内容已进入 `10. 未决问题`
